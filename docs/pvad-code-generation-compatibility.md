# PVAD Code Generation And Worker Compatibility

## Current Output

JSON conversion generates three C# representations with a `Generated by PVAD`
header: readable C# Model, semantic C# PDF Builder and the Base64 transport loader.
The canonical document, element IDs, extension data and customer strings are not
renamed. A document containing PXA or Canvas text retains that text after generation
and execution. Explicit regeneration changes generated source and its checksum;
it does not rewrite an existing saved source draft silently.

The Code Workspace PDF download uses `pvad-code.pdf`. It does not change the PDF
bytes or the document-name handling of normal Designer export.

## Worker And Protocol

The API starts `PVAD.CodeWorker.dll` or the matching executable from the configured
worker directory. Build/publish packaging and container paths use the renamed
project under `src/Execution/PVAD.CodeWorker`. New temporary execution directories
use `pvad-code-`; request/response filenames remain neutral.

The worker references PVAD.Core, PVAD.Generator and PVAD.Pdf assemblies and imports
their current namespaces. Neutral request fields remain language, source, operation,
timeoutSeconds, maximumPages and maximumElements. Language IDs, source-map IDs,
page/element limits, timeout handling and legacy PXACODE diagnostic IDs are unchanged.
Known diagnostic aliases and the existing dual element-marker reader remain active.

Deploy API and worker together. A protocol-field check is not proof that an old
binary can compile code referring to newly renamed assemblies. Old first-party
namespace references require regeneration or explicit source migration; diagnostic
compatibility does not provide assembly or namespace shims. No blanket replacement
is applied to customer source, comments or document contents.

## Validation And Limits

Executable regression tests cover packaged worker startup, the twelve directed
conversions between JSON, C# Model, C# PDF and Base64, DTO field coverage, source maps,
legacy markers, rich text, page geometry and sandbox failure paths. Additional tests
check the generated PVAD headers and preservation of customer text in all three C#
representations. Source contracts guard owned imports and worker packaging paths.

Sandbox filtering, assembly selection and execution limits are not broadened by this
rename. These tests are regression checks, not an independent sandbox security
certification or evidence that production isolation is fully hardened. Deployment
hardening and complete provider-feature permutations remain separate acceptance gates.

## Provider Compilation And Execution Matrix

`MigrationGeneratedCodeExecutionTests` selects a basic fixture from each registered
PDF Code and Spreadsheet Code provider's existing tests using Roslyn syntax nodes.
It does not maintain a separate provider list. Generated source is compiled with
platform and PVAD metadata references, not vendor SDK metadata references, and then
executed as trusted synthetic test code in a collectible assembly context.

The current matrix includes 16 PDF and eight Spreadsheet providers:

- Fifteen PDF fixtures compile and produce PDF files with PDF header/EOF markers.
- Eight Spreadsheet fixtures compile and produce XLSX packages that reopen through
  the PVAD importer with sheets and cells.
- The Pdftools SDK provider deliberately retains vendor code with its existing
  manual-migration diagnostic. Its contract is checked, but vendor code is not
  compiled or executed and no automatic migration success is claimed.
- IronPDF's basic output remains a diagnosed scaffold; producing a PDF does not
  establish HTML rendering fidelity or promote provider support status.
- The workbook builder's documentation example is parsed, compiled and exported
  separately, checking that its public PVAD API names are executable.

Fixture output paths are bound to a temporary directory. A fixture that only builds
a workbook receives a test-harness save call; other source behavior is not repaired
by the harness. These trusted examples are not a production C# execution service,
and this test harness must never accept uploaded or otherwise untrusted source.
Report Designer and Viewer adapters produce different artifacts and are not included
in this C# compilation matrix. Full feature permutations, rendering fidelity and
provider-specific unsupported operations remain separate functional coverage.

### EPPlus Resource Declarations

EPPlus migration removes `using` from converted `ExcelPackage` declarations because
the generated `PvadWorkbook` is not disposable. Typed declarations are updated as
well. Resource blocks become ordinary blocks, preserving lexical scope. Unrelated
resources such as MemoryStream retain their own `using` declarations.

Existing CANMIG diagnostic IDs and vendor names remain unchanged. Spreadsheet XML
examples and current diagnostic wording use PVAD/PVADS names; historical stored
reports and customer source are not rewritten.

Compiler warning PXA0001 and CANMIG provider IDs retain their documented legacy
contracts. Vendor identifiers and neutral PDF/Spreadsheet API concepts are not
renamed as product branding.
